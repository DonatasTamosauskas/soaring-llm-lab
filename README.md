# Soaring LLM Lab

One brief, many builds. Different models and agent tools each build the same game: a VR bird
for Meta Quest that flies by flapping your arms, Gorilla Tag meets agar.io. This repo keeps every
build, the exact prompt it started from, its logs-derived cost and effort, code statistics,
screenshots and video, and your playtest scores, so models can be compared on the same task.

The game itself continues in [DonatasTamosauskas/soaring](https://github.com/DonatasTamosauskas/soaring),
spun out of the Opus 5.5 run.

**Full report**, with every run's phases, screenshots, videos and notes:
https://donatastamosauskas.github.io/soaring-llm-lab/. GitHub Pages rebuilds it from the committed
data on every push to `main` ([pages.yml](.github/workflows/pages.yml)); in a clone, open
`report/index.html`.

## Layout

```
prompts/        every brief, word for word, never edited (README: which run used which)
runs/<date>-<engine>-<model>/
  run.json      you: model, agent tool, engine, prompt, phases ("v1 delivered"), chosen media
  project/      the build as the agent left it
  metrics.json  generated: tokens, cost, time, your messages, code, commits, per phase
  human-messages.md  generated: everything you typed during the run
  checks.json   generated: import check and start-up capture (Godot)
  media/        generated: compact screenshots and videos
  review.md     you: playtest scores against eval/rubric.md
references/     projects given to agents as examples (Unity Quest bootstrap)
eval/           METHOD.md (what every number means), rubric, capture protocol, pricing, run template
tools/lab/      the pipeline: python3 tools/lab --help
tools/capture_godot.sh   import check and start-up capture of a Godot build
report/         generated HTML report (the same page GitHub Pages serves)
.github/workflows/pages.yml   publishes the report to GitHub Pages
.claude/        impeccable, the design skill used on the report (Claude Code, this project only)
raw/            archived agent logs (not in git: private and large)
```

## Adding a run

1. `python3 tools/lab new <yyyy-mm-dd>-<engine>-<model>` creates the folder from
   `eval/run-template/` with the log locations filled in.
2. Put a new brief in `prompts/` as a new file (never edit an old one) and name it in `run.json`.
3. Start the agent in `runs/<run>/project/` and paste the prompt as is. Note the agent tool, mode
   and effort in `run.json`. Let it commit in this repo rather than create its own.
4. When it is done, set the milestones in `run.json`: at least "v1 delivered" with
   `"headline": true`, the moment before your first request that goes beyond the brief.
5. Pick media in `run.json`, and a `cover` among them for the report, then
   `python3 tools/lab all`, and for Godot builds `tools/capture_godot.sh <run>`.
6. Play it and fill in `review.md`.

## Keeping it current

`python3 tools/lab all` archives new logs, rebuilds media, recomputes metrics and regenerates the
leaderboard and report; commit and push, and the site follows. Archive early: Claude Code deletes
transcripts after `cleanupPeriodDays` (30 by default), which is how the Opus 5 run lost its logs.

Requirements: Python 3.9+ (standard library only), git, ffmpeg (on PATH or
`~/.juicylucy/bin/ffmpeg`), and Godot 4.7.2 for captures.
