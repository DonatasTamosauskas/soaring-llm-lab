# Method

How every number in the leaderboard and report is produced, and where it stops being comparable.
All of it is regenerated by `python3 tools/lab all` from the files in this repo plus the archived
logs in `raw/` (kept out of git).

## A run

`runs/<start date>-<engine>-<model>[-variant]/`:

| File | Written by | What it holds |
|---|---|---|
| `run.json` | you | model, agent tool and mode, engine, prompt, status, summary, log sources, phase boundaries, chosen media |
| `project/` | the agent | the build exactly as the agent left it |
| `metrics.json` | `tools/lab collect` | everything below, per phase |
| `human-messages.md` | `tools/lab collect` | every message you typed during the run, with times |
| `checks.json` | `tools/capture_godot.sh` | import check and start-up capture (Godot builds) |
| `media/` | `tools/lab media`, capture script | compact screenshots and videos for the report |
| `review.md` | you | playtest scores against [rubric.md](rubric.md) |

## Phases: "measured up to"

Runs continue after the game is built: showcase videos, headset installs, prompt retrospectives.
`run.json` marks phase boundaries as `milestones`, each with a time and the reason it was chosen
(usually one of your messages). Every metric is computed up to each boundary and for the whole
run. The leaderboard compares runs at the milestone marked `"headline": true`, which is "v1
delivered" (the moment before your first request that is not part of building the brief), and
says so in the "Measured up to" column. A run without one is compared on its whole log.

## Cost and tokens

- **Tokens** are normalised to: uncached input, cache writes (5-minute and 1-hour), cache reads,
  output (including reasoning). Claude Code reports these separately; Codex counts cached tokens
  inside its input total, so they are subtracted.
- Claude Code logs one API response several times as it streams; each response is counted once,
  with the largest value of each field. Synthetic entries (`<synthetic>`) are ignored.
- Codex keeps one file per thread. Subagent threads (forked with a copy of their parent's history,
  marked by `subagent_history_start_ordinal`) and Codex's automatic review threads are included;
  the copied history is skipped so nothing is counted twice.
- **Est. API cost** = tokens × [pricing.json](pricing.json): list prices, not your bill. You ran
  these on subscriptions, which bill differently. Codex prompts over 272K tokens are billed at a
  higher tier that is not modelled, and the review model is priced as `gpt-6.1-sol`, so Codex costs
  are a lower bound.
- **API calls / turns**: Claude Code API responses, or Codex token-count events (about one per turn).

## Time

- **Active time**: per thread, consecutive log events up to 10 minutes apart form a working
  interval; the union of all threads' intervals is the active time. A tool call that runs over 10
  minutes without logging counts as idle, so this undercounts slightly: with a 20-minute cut-off
  Unity Sol rises from 1.8 to 2.3 hours; the other runs barely move.
- **Agent time**: the same intervals added up across threads, so parallel subagents count fully.
  Agent time ÷ active time is the "parallel" factor.
- **Wall clock**: first to last log event, including nights and your review time.
- Runs without logs show the span from the agent's first to last commit, marked "(commits)": a
  rough lower bound.

## Human involvement

- **Human messages**: messages you, the person running the experiment, typed. Claude Code marks them (`origin: human`); older entries
  are told apart from command output, notifications and tool results by their markers. In Codex,
  user-role entries the app injects (environment, open page, in-app browser state) are dropped and
  the text after a browser-state block is kept. Prompts between agents never count.
- **Stops**: times you interrupted a running turn.
- Settings changed with slash commands (`/model`, `/effort`) are listed in `human-messages.md`.

## Code

Measured on the files git tracks in `project/`, so ignored build output never counts.

- Third-party and engine-generated folders are excluded: Godot `addons/`, `android/`, `.godot/`;
  Unity `Library/`, `Packages/`, `ProjectSettings/`, `UserSettings/` and imported samples and
  packages under `Assets/` (`Samples`, `VRTemplateAssets`, `TextMesh Pro`, `XR`, `XRI`,
  `CompositionLayers`, `Oculus`, `Plugins`). A run can add more in `code_exclude`.
- Lines are non-blank lines. Each code file is **game** code, **test** code (a `tests`/`test`
  folder or a test-named file) or **tooling** (Python, shell, `tools/`, Unity `Editor/`).
- **Test code** is the comparable measure of testing. Every Godot build wrote its own harness
  (`_run_all()`, `ok()`, `func test_…`), so a count of tests is not comparable; `metrics.json`
  keeps `tests_defined` (xUnit-style definitions: GDScript `func test…(`, C# `[Test]`/`[UnityTest]`,
  Python `def test_…(`) for the builds that use one. The agents' own suites are not re-run yet.
- **Docs**: non-blank Markdown lines. **Assets**: textures, models, audio and video by count and
  size. Scenes and data files (`.tscn`, `.tres`, `.unity`, `.prefab`, `.asset`, `.json`, …) are
  counted separately.
- **Commits**: commits touching the run's current or earlier paths, minus lab housekeeping
  ([housekeeping-commits.txt](housekeeping-commits.txt), or a `Lab-Housekeeping:` trailer).

## Checks and media

- **Import check** (Godot): `tools/capture_godot.sh` copies the project to `raw/_work/`, imports
  it headless with the installed Godot and counts script and parse errors. Godot 4.7.2 sometimes
  crashes while exiting after a finished import; that is recorded as `crashed_on_exit` and does
  not fail the check.
- **Start-up capture** (Godot): the main scene in a desktop window, XR off, Forward+, 1280×720,
  fixed 30 fps, no input, for 12 seconds, through Godot's movie writer. It shows what each build
  presents on launch, not gameplay. See [capture-protocol.md](capture-protocol.md).
- **Chosen media**: screenshots and videos the agents made, listed in `run.json` and converted by
  `tools/lab media` to JPEG (≤1600 px wide) and H.264 MP4 (≤720 px high).

## Comparability: read before ranking

- **Prompts differ.** Each run's prompt is in [../prompts](../prompts); several are revisions
  made between runs, so later runs had better briefs.
- **Agent tools and modes differ**: Claude Code with multi-agent workflows (Opus 5.5) against
  single-agent Codex (Sol 6.1). Settings are recorded per run.
- **Your steering differs**: count and read `human-messages.md`.
- **Logs are missing** for Opus 5 (deleted by Claude Code after 30 days) and both Prime Muse runs
  (never kept); Fable 5.1's local log covers only 23 API calls of an 8.5-hour session.
- **Not yet verified**: Unity builds have no automated import check or start-up capture yet
  (their Library folders were cleared and need a re-import), and no build has a standard gameplay
  capture or a playtest score yet.
