# Soaring contracts
Unity 6000.6.4f1; OpenXR 1.18, URP mobile, Meta Quest Pro / ARM64. Source project `Soaring/`. Runtime namespace `Soaring`. All distances metres, size starts at 1.

Root owns `FlightTuning`, `FlightModel`, `BirdPlayer`, `GameSession`, `SoaringBootstrap`, tests, builds. World agent owns `BirdWorld.cs`, `NpcBird.cs`, geometry/helpers only. UI agent owns `BirdUI.cs`, audio and HUD/menu only. Do not edit other ownership areas. No commits by agents; root commits milestones.

`GameSession` singleton `Instance`: public `BirdPlayer Player`, `BirdWorld World`; properties `bool IsPlaying`, `bool IsPaused`, `bool IsDead`, `bool HasWon`, `float Mass`, `float Size`, `float Elapsed`, `int Catches`, `int ApexRings`, `string Status`; methods `StartRun()`, `Pause(bool)`, `Restart()`, `Catch(float preySize)`, `Kill(string reason)`, `ApexRing()`; `event Action Changed`. Size = cube root mass. Tunable pacing lives in FlightTuning.

`BirdPlayer`: public `FlightTuning Tuning`; `Transform Head`, `LeftHand`, `RightHand`; properties `Vector3 Position`, `Vector3 Velocity`, `float Speed`, `float Size`, `bool IsCalibrated`, `bool TrackingValid`, `bool DesktopMode`, `float Extension`, `float TurnInput`; methods `CalibrateRelaxed()`, `CalibrateExtended()`, `ResetFlight()`, `Haptic(float strength,float duration)`. Root yaw only, no flight pitch or roll. Public `bool ComfortVignette`, `bool HapticsEnabled`. XR menu controls forwarded to UI by polling; player checks UI pause. Desktop fallback documented.

`BirdWorld`: public `float ArenaRadius=240`, `float Ceiling=150`; methods `Build()`, `ResetPopulation()`, `float UpdraftAt(Vector3)`, `Vector3 Constrain(Vector3,float radius)`, `bool ObstacleAhead(Vector3,Vector3,float distance)`. public `List<NpcBird> Birds`; `NpcBird`: public float Size; public bool Alive; public Vector3 Position. World owns catch/hunt interactions via session.Catch/Kill, boundaries, respawning, apex rings and gates. World built once from Bootstrap after session/player wiring, no implicit Start build. `SliceMode` public bool limits population to one catchable bird (root milestone 1).

`BirdUI`: public `GameSession Session`; `BirdPlayer Player`; method `Build()`, public `bool MenuOpen`; world-space UI, controller ray + trigger AND thumbstick focus + primary select, desktop mouse/keyboard. State drives calibration/menu/pause/death/victory. UI can access tuning via reflection of `[Range]` floats (all tuning public float fields), Save/Load/Reset methods on Tuning. Boot calls Build after wiring. UI owns input menu toggles (left menu or secondary, desktop Escape), uses unscaled time. Status HUD world-space. Do not rely on prefab XRI locomotion; root builds custom tracked rig.

World visuals use shared materials, primitive or low polygon meshes, no asset downloads. Static environment batching; budget <=96 active birds, <=1500 renderers. World coordinate bounds close arena softly. NPC max speed <= player base cruise at equal size. Target NPC seek/flee includes each other. All pause timers freeze. Tracking loss pauses game automatically.

Presentation owner (root): `SanctuaryPresentation` sets the graduated stereo sky, sun/ambient/fog and bounded catch particles after world creation; it never changes camera pose or flight. `PlayerWingArt` supplies layered feather geometry combined into three materials per tracked hand. World and UI agents retain their existing ownership during the visual corrective pass. Primitive construction is an implementation detail; final silhouettes, scene depth and UI hierarchy are reviewed through simulator captures rather than a renderer-count-only acceptance.

Showcase owner (root): `SoaringShowcase` is attached only by the `--showcase <directory>` CLI flag. It provides scripted `WingSample` inputs to the shared flight model and uses ordinary world catch/goal contacts; growth montage cuts call the session catch API explicitly. It disables tracked player polling during takes, applies unsaved safety/comfort tuning, and renders a mono URP camera to 1080p PNG frames at a fixed simulated 30 fps. The manifest records shots, procedural sound event times and contact/goal counters. `scripts/edit-showcase.py` uses those frames, exported game sound clips and an original procedural score to create the disclosed showcase MP4. This harness supplies presentation evidence, not human pacing, comfort or device performance measurements.
